# F5: rutas con IA. Plan de implementación

> **Prioridad móvil (2026-11-07).** Rige `docs/requisito-mobile-first.md`. Las pantallas de este plan se implementan siguiendo el prototipo móvil `docs/design/prototipo-movil/` (README, kit `movil.css`/`movil.js` y la página correspondiente), que prevalece sobre las descripciones de interfaz de este plan si chocan. La lógica, las interfaces y las pruebas del plan siguen vigentes.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** en Rutas, el modo «Con IA» hace cuatro preguntas (qué entrenar, tiempo disponible, inicio, repetir o descubrir). La IA las convierte en 3 a 5 objetivos que apuntan entre un 5 y un 15 % por encima de la referencia del usuario. ORS genera una ruta por objetivo. Cada ruta se muestra con una explicación que cita sus cifras y se descarga en GPX. Si la IA falla dos veces, aparece el formulario manual de F4 ya relleno.

**Architecture:**
- El navegador llama directamente al proveedor de IA compatible con OpenAI (`POST {baseUrl}/chat/completions`, Groq por defecto). Groq admite CORS (`docs/verificaciones.md`, paso 5), así que no hace falta Worker.
- Dos llamadas por búsqueda:
  1. **Plan:** recibe el resumen del nivel y las respuestas, y devuelve los objetivos en JSON con esquema estricto.
  2. **Explicación:** recibe las cifras de las rutas que ha calculado el código y devuelve un texto por ruta.
- El código valida cada JSON con zod, ajusta los objetivos al rango del 5 al 15 %, llama a `generateRoutes` de F4 y comprueba que cada explicación cite cifras reales.
- A la IA solo le llegan cifras resumidas: nunca coordenadas, tracks ni la dirección de Casa. El inicio lo elige el usuario en el mapa y solo va a ORS.

**Tech Stack:** el de F4 más `zod` 4 (`z.strictObject`, `z.toJSONSchema`).

**Spec:** `docs/superpowers/specs/2026-11-06-plataforma-ciclismo-design.md` (decisiones 5, 6, 7 y 11), `docs/superpowers/plans/2026-11-06-f4-generador-rutas.md`, `docs/verificaciones.md`

## Global Constraints

- Las de F1 y F4 siguen vigentes.
- Las pruebas nunca usan claves reales ni hacen llamadas reales: `fetch` se inyecta o se simula, y en Playwright se usa `page.route`.
- Privacidad: el cuerpo de cualquier petición a la IA no contiene coordenadas, tracks, la dirección ni las coordenadas de Casa, ni los nombres de las actividades. Lo cubre una prueba (tarea 5).
- Cuerpo de la llamada: `{ model, messages, response_format: { type: 'json_schema', json_schema: { name, strict: true, schema } }, temperature: 0.3 }`. No se envían parámetros propios de Groq, para no romper otros proveedores compatibles.
- Reintento: si el JSON no es válido (no se puede leer, zod lo rechaza o el proveedor da 400 de esquema), se repite una vez y se añade el error al mensaje. Si vuelve a fallar:
  - en el plan, se muestra el formulario de F4 relleno con los objetivos que calcula el código;
  - en la explicación, se usa un texto que genera el código.
  Los errores 401, 429 y de red no se reintentan.
- Objetivos: entre un 5 y un 15 % por encima de la referencia en la dimensión elegida. Si la IA se sale del rango, el código lo recorta. El tiempo disponible limita la distancia (`minutos · 60 · avgSpeedMs`) y tiene prioridad sobre el 5 %.
- Coste de ORS por búsqueda: de 3 a 5 opciones, con `count: 1` y `seeds: 3` en cada una. Como mucho, 15 peticiones, por debajo de 40 por minuto.
- Con menos de 5 salidas (`computeReference` devuelve `null`) se hacen 3 preguntas iniciales: distancia habitual, desnivel habitual y velocidad media habitual. Las respuestas se guardan y sirven de referencia declarada.
- Diseño visual provisional.
- Skills: `karpathy-guidelines` y `superpowers:test-driven-development` en todas; `react-best-practices` en componentes; `web-design-guidelines` y `break-ui` al cerrar.

## Review Focus

1. **La IA devuelve JSON no válido dos veces:** el usuario no se queda bloqueado; ve el formulario de F4 ya relleno. Tarea 5: `invalid twice falls back with suggested target`; tarea 6: `fallback shows prefilled manual form`.
2. **Datos privados en la petición:** ni Casa ni el inicio elegido ni los tracks llegan a la IA, aunque el usuario escriba notas. Tarea 5: `ai requests never include home, start or tracks`; tarea 6: el aviso del campo de notas.
3. **Groq al límite (429):** mensaje con los segundos de espera, sin reintento automático y con el formulario manual disponible. Tarea 4: `429 maps to rate_limit with retry-after`; tarea 6: `rate limit shows wait and manual form`.
4. **Poco tiempo para subir un 5 %:** si con el tiempo disponible no se llega a la referencia + 5 %, manda el tiempo y la explicación lo dice. Tarea 5: `time cap below uplift keeps time limit and flags`.
5. **Modelo sin salida estricta** (por ejemplo `llama-3.1-8b-instant`): el 400 se explica y se sugiere `openai/gpt-oss-20b`. Tarea 4: `400 response_format unsupported maps to model_unsupported`.
